# DBMS Experiment 4: Joins, Subqueries, Existence Checks & Query Execution Plans

## Aim
To perform and analyze advanced SQL queries using `INNER JOIN`, `LEFT JOIN`, `SELF JOIN`, multi-way joins, correlated subqueries, `EXISTS`/`NOT EXISTS` predicates, and to inspect query execution plans using `EXPLAIN`.

## Prerequisites
* **Experiment 3 (`DBMS Exp-3.sql`)** must be executed first so that the `EmployeeManagement` database and its populated tables (`Department`, `Employee`, `Project`, `Employee_Project`) exist.

## Key SQL Concepts Demonstrated
1. **`INNER JOIN`:** Retrieves matching records between `Employee` and `Department`.
2. **`LEFT JOIN`:** Lists all departments alongside their employees, ensuring departments with zero employees are still included.
3. **`SELF JOIN`:** Pairs employees working in the same department using `e1.emp_id < e2.emp_id` to prevent self-pairing and duplicate reversed pairs.
4. **Multi-Way Joins (3-Way / 4-Way):** Connects `Employee`, `Department`, `Employee_Project`, and `Project` to display which employees are working on which specific projects, as well as department-level project ownership.
5. **Correlated Subqueries:** Identifies employees earning more than the average salary of their specific department.
6. **`EXISTS` & `NOT EXISTS` (Simulated `INTERSECT` / `EXCEPT`):**
   * Finds employees assigned to at least one project.
   * Finds IT employees (`dept_id = 1`) working on Project `201` (`EXISTS`).
   * Finds IT employees (`dept_id = 1`) *not* working on Project `201` (`NOT EXISTS`).
7. **Query Optimization Analysis (`EXPLAIN`):** Uses the `EXPLAIN` keyword before `INNER JOIN`, `LEFT JOIN`, correlated subquery, and `EXISTS` statements to inspect table scan types, key usage, and row estimates.

## How to Run
1. Verify that `EmployeeManagement` is populated from Experiment 3.
2. Run `DBMS Exp-4.sql` in MySQL.
3. Review the tabular outputs for the queries and the execution plan metrics (`type`, `possible_keys`, `key`, `rows`, `Extra`) generated by the `EXPLAIN` statements.
